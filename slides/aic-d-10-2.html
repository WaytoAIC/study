五种 Workflow 模式：五个电商场景

决定"写死流程"之后，还有第二个问题：这几步怎么排？业界验证过的排法就五种，由简到繁。这一页把五种排法各配一件你手上的活，附带每种要付的代价。

学先把这个点看明白五种排法 · 各配一件电商的活

这五种模式不是我们发明的，是业界（Anthropic 的公开工程文章）总结出来的五种编排方式，通用版那节讲的是原理和通用例子；这一页只做一件事：把五种排法各换成一件跨境电商的真活，并说清每种的代价。看完你应该能对着自己团队的流程说出："这件活是第几种。"

1
一步接一步，中间设关卡Prompt Chaining · 提示链

把一件大活拆成几步，上一步的产出就是下一步的输入；步与步之间可以插一道关卡，不合格就打回，不往下传。最简单，也最常用。

卖点清单
写标题 + 五点
关卡：核心词 / 禁用词 / 字数
目标语言本地化
按站点模板排版
电商场景 · 新品上架文案管道

一件件来：先让 AI 从产品资料里抽卖点，再写标题和五点，过一道关卡（核心词在不在、有没有踩禁用词、字符数超没超），过了才翻成德语日语，最后按各站点模板排版。

关卡是这个模式的灵魂：标题里漏了核心词这种错，如果不在这里拦住，后面会被原样翻译成五个语种、排进五份模板——错误会被流水线放大。

代价：步数越多越慢，token 也随步数涨。还有个隐蔽的坑——下一步只看得到上一步交出来的东西，所以每一步的交付格式要写死，否则信息一步步漏。别用在：一句话就能出结果的活，别硬拆五步。
2
先分类，再分流Routing · 路由

进来的东西不是一类，就先用一道分类，把它送进对应的专门通道。每条通道有自己的提示词、自己的资料、甚至用不同的模型。

买家来信
分类
物流查询 → 模板直回
退款纠纷 → 接订单数据起草，人确认
产品使用 → 接知识库
差评 / 投诉 → 直接转人
电商场景 · 客服来信分流

物流查询占大头，用便宜快的模型套模板就够；退款纠纷要调订单数据、要斟酌措辞，用强模型起草、人点头再发；差评和侵权投诉根本不进 AI 通道，直接转人。

两个收益：省钱——大部分简单来信不需要动用贵模型；各管各的——一个提示词想通吃所有来信，结果是哪一类都答得不好。

同样的排法还能用在别处：新线索进来先分类，做过的类目直接调历史结论，没做过的才走完整调研。

代价：分类错了，后面全错，而且错得很自然、不容易发现。两条保险——给分类器一条"拿不准就转人"的出口，以及定期抽查分类结果（尤其是转人那一类有没有被误分到自动回复）。
3
同时跑，最后合Parallelization · 并行

几件互不相干的事同时跑，再把结果合起来。两种用法：拆开并行（一件活拆成几路，各查各的）和多跑几次投票（同一件事跑几遍，取多数）。

一条竞品 Listing
主图看什么
标题五点怎么写的
评论里的痛点
汇总成一页对比
电商场景 A · 拆开并行：竞品体检 / 上架前合规扫

体检一条竞品 Listing，三路同时跑：一路只看主图、一路只看标题五点、一路只扒评论痛点，最后汇总成一页。比一个提示词让它"全面分析一下"强得多——那样出来的东西每项都浅。上架前的合规扫同理：商标、禁用词、类目规则三路并跑。

电商场景 B · 多跑几次投票：拿不准的判断

同一段文案，让它独立判断三次"有没有夸大宣传或违规风险"，取多数意见；三次结论不一致的，恰恰说明这条是灰区，挑出来给人看。

代价：token 成倍。用在漏判代价大的地方（合规、侵权、要发出去的内容），别用在无所谓对错的活上。还有一个常见误解：投票降的是随机，不是幻觉——它把同一个数字编三遍，投票照样通过。事实类的东西，最后还得回原始数据核。
4
先看一眼，再决定派几路活Orchestrator-Workers · 编排者-工人

一个"工头"先看一遍任务，当场决定拆成几件、每件交代什么，再把活分给几个"工人"，最后把结果合起来。和并行的区别就一句：并行是你事先写死跑哪几路，这里是它看完才知道跑几路。

30 个 SKU 的改写需求
工头：扫一遍，分门别类
服饰类：按尺码痛点改
家居类：按使用场景改
电子类：按参数与合规改
合并 + 统一过品牌词表
电商场景 · 一批 SKU 的 Listing 按新品牌调性重写

你只交代一句"这 30 个 SKU 按新调性改一遍"。工头先扫一遍，发现里头分属几个类目，于是决定分几路、每路带哪套规则、哪几条要先查类目词——这个拆法你事前写不出来，因为它取决于这批 SKU 具体是什么。同样适合季度类目调研：先扫结构，再决定拆成几个子调研。

代价：这是五种里最接近"放手"的一种，账不封顶——工头多拆几路，钱就多花几倍。必配两样：给上限（最多拆几路 / 最多花多久），结果按"数量对不对、有没有漏 SKU"抽查一遍。
5
一个写，一个挑刺，循环改Evaluator-Optimizer · 评估-优化

一个负责生成，另一个拿着你的验收标准挑刺并给出具体修改意见，生成者照着改，循环几轮直到过关或到轮数上限。

初稿
照验收清单挑刺
按意见改
过关 or 到轮数上限 → 交人
电商场景 · 五点 / A+ 文案定稿前的自检循环

挑刺的那一方手里必须有写得出来的标准，例如：有没有空话（放在任何竞品身上也成立的话＝零信息量，删）、核心词有没有自然融入、有没有夸大或违规表述、每条卖点对不对得上买家的顾虑。改两三轮，质量肉眼可见地往上走。

标准不具体，这个模式就废了——两个 AI 会互相吹捧，"很好，建议保持"。

代价与边界：轮数不封顶，给个上限（比如最多三轮，还没过就交给人）。更要紧的是别搞错这一轮的性质——它只是发稿前的自检，真正判对错的是上架之后的数据（而且一次只动一个变量，不然你分不清是哪处改动起的作用）。

五种排法一览

排法电商里的典型活要付的代价复杂度
一步接一步新品文案管道、周报生产线慢；每步交付格式要写死低
先分类再分流客服来信、线索归类分类错了全错，要留转人出口低
同时跑再合并竞品体检、合规多路扫、灰区投票token 成倍；投票不解决编数字中
工头派活一批 SKU 批量改写、类目调研账不封顶，必须给上限 + 抽查中高
写-挑刺-再改五点 / A+ / 本地化文案定稿轮数要封顶；标准不具体就白转中

怎么挑：从上往下问，停在第一个"是"

  1. 一步就能出结果吗？→ 别排，一句话交代完事
  2. 是顺序问题吗（后一步要用前一步的结果）？→ 一步接一步
  3. 进来的东西不是同一类吗？→ 先分类再分流
  4. 几件事互不相干、或想多跑几遍降随机？→ 同时跑再合并
  5. 事前不知道要拆成几件？→ 工头派活
  6. 有写得出来的验收标准、一稿达不到？→ 写-挑刺-再改
这几种能不能混着用？
实际工程里基本都是混的。典型样子是：主干是"一步接一步"，其中某一步里嵌了"先分类再分流"，另一步里嵌了"同时跑再合并"。混用没问题，但每加一层就问自己一次：这层复杂度换来的效果，值不值它带来的等待、花费和排错难度？不值就砍掉。
我不写代码，这些排法跟我有关吗？
有关，而且是你最该懂的部分。三个落地口子：①交代任务时照着排法说清楚步骤和关卡，比"帮我全面分析一下"强一个量级；②写进 Skills——一份 Skills 的核心就是步骤、关卡、验收标准，等于把排法固化下来；③让 Coding Agent 照这个结构搭——你说"先分类，物流类走模板，纠纷类调订单数据后等我确认"，它负责实现。排法是你的活，代码不是。
投票跑三遍，是不是就能把 AI 编数据的毛病治了？
治不了。投票降的是"同一个问题问三次答案飘"的随机性，属于判断题的置信度问题；而编数字是它的老毛病——三次都能编出同一个像模像样的数。凡是具体数字、出处、私有信息，仍然要回原始数据核对，验证力度跟着后果走。
PROMPT · 挑刺方（Evaluator）的验收清单
你是审稿方，不负责重写，只负责按下面的清单挑刺并给出可执行的修改意见。

稿件：[粘贴初稿]
产品与买家背景：[粘贴背景包]

逐条检查，每条给「过 / 不过 + 具体位置 + 怎么改」：
1) 空话检验：这句话放在任何竞品身上也成立吗？成立＝零信息量，删或改具体
2) 核心词：[列出必须出现的词] 有没有自然出现（不是硬塞）
3) 合规：有没有夸大、承诺疗效 / 效果、绝对化用语、平台禁用表述
4) 买家顾虑：[列出该品类买家最担心的 3 件事] 是否都被回应
5) 格式：字符数 / 条数 / 大小写是否符合站点要求

最后给一句总判：过关，还是打回重改（说明最致命的那一处）。
不要夸奖，不要重写全文，只输出清单结果。

FEYNMAN · 输出倒逼输入

面试或复盘场合常见的一问："五种排法你都用过吗？挑三种讲讲，各自适合什么场景、要付什么代价。"
挑你最熟的三种，每种讲：一句话是什么、配哪件电商的活、代价在哪。

  • 每种都说清"一句话定义 + 一件具体的活 + 一个代价"，缺代价那条就是没用过
  • 能说出并行和工头派活的区别：路数是事先写死的，还是它看完才定
  • 能说出关卡的价值：错误别往下传，否则被流水线放大
  • 结尾一句：不追求最复杂，追求最合适；能一步做完就别排五步
练拿真活练一把刻意练习
任务
挑你团队最花时间的那件重复活，画成不超过 5 个框的流程图：每个框写清"谁干、进什么、出什么"，标出用的是哪一种排法、关卡设在哪一步、最后谁验收。
合格标准
流程图能让没做过这件活的同事照着跑一遍；能指出哪一步错了后面全白做（那里就是关卡该在的位置）。
实跑
照图实跑一次，记录：总用时、哪一步返工最多、关卡拦住了几次。返工最多的那步，考虑拆细或加挑刺循环。
衡量口径：流程图（≤5 框，标了排法与关卡）+ 一次实跑记录（用时、返工步、关卡拦截次数）。下一轮和这轮比。
  • 挑定一件最花时间的重复活
  • 画成 ≤5 个框，标出排法与关卡
  • 照图实跑一次并记录
  • 把返工最多的那步改掉，再跑一次
