写死流程还是放手：Workflow 和 Agent 怎么选

同一件活，写成固定流程，AI 每次跑法一样、花多少钱你心里有数；交给 Agent，它自己决定下一步，能干你没想到的活，也可能绕一整圈烧掉一堆钱。选错了，要么白花钱，要么不敢用。

学先把这个点看明白两种干法 + 三问选法

把 AI 用进业务，说到底只有两种干法：路线你先画好，AI 只在每个框里干活（术语叫 Workflow，下文叫"固定流程"）；或者你只给目标和工具，AI 自己决定先干什么、干到哪算完（术语叫 Agent，下文叫"放手"）。这两个词天天被混着用，但它们对应的成本、风险和管理方式完全不同。想看机制原理与通用定义，去基础轨的通用版（页尾关联可跳）。

固定流程（Workflow）

你把步骤写死：先拉数，再筛词，再出表。AI 是流程里的工位，不是司机。同样的输入进去，走的是同一条路，出来的东西可以对照上一次看。

每次一样 · 能复盘 · 花多少钱能估

放手（Agent）

你交代的是目标："查清楚这个 ASIN 的流量为什么掉了。"它自己决定先看广告还是先看排名，查到哪一步算查明白了，也由它判断。

能应付没预想到的情况 · 每次路线可能不同 · 账不封顶

同样是电商的活，哪些该写死、哪些该放手

你手上的活该怎么干为什么
每周一的类目关键词周报：拉数 → 筛词 → 出表 → 发群固定流程步骤早就定死了，每周不变。放手只会让它今天多查一段、明天少查一段，你还没法跟上周对比。
新品上架文案：卖点 → 标题五点 → 合规检查 → 多语言 → 排版固定流程顺序本身就是质量保证，中间那道合规检查必须每次都跑，不能由 AI 心情决定跑不跑。
"这个 ASIN 昨天流量掉得厉害，去查原因"放手原因可能在广告、排名、竞品降价、Listing 被改、库存断货。下一步查哪里，取决于上一步看到了什么——这种路线你事前画不出来。
"把这个类目摸一遍，告诉我值不值得做"放手 + 人裁决调研路径随发现而变，适合放手；但"值不值得做"这句结论必须回到你手里裁（人出标准与裁决，AI 出执行与反方）。
每天算一次各 SKU 的实际到手利润连 AI 都不用这是算术，不是判断。能用公式和脚本算死的，别花 token——先过一遍「把重复任务变成 Skills」那节的两个维度。

选法：三个问题，问完就有答案

1

路线能不能提前画死？

拿张纸把步骤写下来，写得出来、且下次还是这几步 → 固定流程。写到第二步就卡住"这得看第一步查出什么" → 这块得放手。

2

每次进来的东西是不是同一类？

都是同一种输入（同一张报表、同一类商品）→ 一条固定流程吃下。五花八门（客服信里什么都有）→ 先加一道分流，分完各走各的固定流程（就是下一节的「路由」模式），仍然不用放手。

3

跑错了谁兜？

出错要赔钱、要能查是哪一步错的（改价、发货、回买家）→ 固定流程 + 人工确认点。错了顶多白跑一趟（调研、找线索、写初稿）→ 可以放手。验证力度跟着后果走。

和前面两套判断不打架，它们管的是不同层：挑活三筛问"这活值不值得交出去"；两个维度（需要不需要智能 × 结果能不能验证）问"交给 AI 还是交给脚本"；这三问问的是最后一层——"交给 AI 之后，是按固定流程跑，还是让它自己定路线"。

别一上来就要建 Agent：复杂度是成本，不是功能

  1. 先试一句话交代清楚：把五要素（干什么/给谁/背景/格式/不要什么）补全，很多活到这一步就够了。
  2. 不够？把料喂上：把你的背景包、报表、历史结论贴进去，让它有依据可查，而不是靠猜。
  3. 还不够？拆成固定流程：把一件大活拆成几步，每步单独交代，中间设关卡（下一节讲五种排法）。
  4. 真的画不出路线，才放手：给目标、给工具、给停止条件，让它自己决定路径。

多数卖家的现实是：第一、二级就能解决的活，被做成了第四级。每往上一级，你多付的是等待时间、token 账单和"出了事查不出哪一步错"的调试成本。只有在明确看到效果提升时，才往上走一级。

⚠︎ 别被名字骗了：叫 Agent 的东西，里面多半混着固定流程

实战四那个「多店铺巡检 Agent」，拆开看是两段：取数、算指标、出表这一段是写死的（每天都一样，才有得比）；只有"这条异常该往哪查"那一段是放手的。所以"要不要上 Agent"这个问题问得太粗——正确问法是：这件活的哪一段路线是画得死的，哪一段画不死。

① 取数（写死）
② 算指标（写死）
③ 异常往哪查（放手）
④ 出报告（写死）
别人都在做 Agent，只用固定流程是不是落后了？
反过来：能写死的活还放手，才是外行。固定流程的三个好处是花钱买不来的——账可预估（调用次数固定）、能复盘（每次同一条路，错了知道错在哪一步）、能验收（结果格式一致，可以和上周比）。天天要跑的活尤其如此：每天跑一次的巡检，路线每次都不一样，你连"今天比昨天差在哪"都说不清。
放手之后怎么控账、控风险？
放手不等于撒手，给三道护栏：①上限——最多查几步、最多花多久，到了就停下来报告；②默认只读——放手的活先只给查数据的权限，别给改东西的权限；③人工确认点——凡是会产生实际后果的动作（改价、改库存、回买家、下架），一律停下来等人点头。安装时给了工具授权，不等于给了业务操作授权。
同一件活能不能一半写死、一半放手？
这才是实际工程里最常见的样子。上面巡检的例子就是：固定流程的某一个框里，塞一段放手的处理。做法是把"画得死的部分"尽量画死，把放手的范围缩到最小的那一段——放手的面积越小，账越可控、越好排错。

放手型任务的交代模板（三道护栏写进提示词）

  • 目标与完成标准：查什么、拿到什么算查完（不写清楚，它会一直查下去）
  • 工具与权限：能用哪些数据源；本次只读，不改任何线上内容
  • 停止条件：最多查 N 步 / N 分钟，到了就把当前结论和没查完的部分一起交出来
  • 必须停下来问我的动作：改价、改库存、回买家、下架、对外发送——列成清单
  • 交付格式：结论先行，每条结论后面附它是从哪看出来的（方便你抽查）
PROMPT · 放手型任务的护栏式交代
目标：查清楚 [ASIN / 店铺] 最近 [时间窗] [出了什么异常] 的原因。
完成标准：给出最可能的 1-3 个原因，每个原因后面附你看到的证据。查到能支持结论就停，不用穷尽。

可用数据：[列出它能查的报表 / 后台 / 工具]
权限：本次只读。不要修改任何线上内容。

停止条件：最多查 [N] 步；到上限就把当前结论 + 还没查的方向一起交出来。
必须先问我再做的动作：改价、改库存、改 Listing、回买家、下架、对外发送。

输出格式：
1) 结论（1-3 条，按可能性排序）
2) 每条结论的证据（数据来自哪张表 / 哪个页面）
3) 你排除掉的方向，以及为什么排除
4) 你不确定、需要我确认的地方
示例模板 · 待维正替换实战版。用法：放手型任务每次都带这五段，缺一段它就会自己发挥——最常见的翻车是没写停止条件，结果绕圈到你喊停。

FEYNMAN · 输出倒逼输入

运营问你："既然 AI 这么聪明，周报为什么不做成 Agent 让它自己跑？"
用三分钟讲清：周报为什么要写死，而"流量为什么掉了"为什么可以放手，以及放手要配哪几道护栏。

  • 周报：路线画得死 + 要和上周比 → 写死才有可比性，账也固定
  • 查原因：下一步取决于上一步看到什么 → 路线画不出来，只能放手
  • 放手三护栏：上限（步数/时间）、默认只读、有后果的动作等人点头
  • 加一句：叫 Agent 的产品里，固定的那几段其实还是固定流程
练拿真活练一把刻意练习
任务
列出你本周交给 AI 的 3 件活，每件过一遍三问（路线画不画得死 / 输入是不是同一类 / 错了谁兜），给出结论：写死、放手，还是其实用脚本就够。
合格标准
3 件活各有结论和理由；至少找出 1 件被做复杂了的（本来一句话提示词或一个公式就够，却做成了多步流程或放手）。
加练
挑其中该放手的那件，用上面的模板写一份带三道护栏的交代，实跑一次，记录它实际走了几步、有没有撞到你设的上限。
衡量口径：3 件活的分类结论 + 1 件"被做复杂了"的活 + 放手任务的实际步数与停止情况。
  • 列出本周交给 AI 的 3 件活
  • 每件过三问，写下结论与理由
  • 找出至少 1 件被做复杂了的
  • 给放手那件写护栏交代并实跑一次

本页 Takeaway：路线画得死就写死，画不死才放手；三问＝路线能不能画死、输入是不是同一类、错了谁兜；复杂度是成本不是功能，多数活停在"一句话+喂料"就够；放手必配三护栏（上限、默认只读、有后果的动作等人点头）；叫 Agent 的东西，里面多半混着固定流程。
