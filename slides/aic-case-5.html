把业务 SOP 转 Skills

团队已经有 SOP 的，不用从对话里慢慢攒，可以直接转。难的不是写，是把人脑里的"我知道怎么做"，变成 AI 能读懂、执行和验证的规则。

整理自维正 2026-09-16 直播《任务设计：把工作交给 AI》· 系列课《从0打造，AI Native 跨境电商》第②讲

学先把这个点看明白筛选 → 拆解 → 显化 → 封装 → 验证 → 迭代

核心：不是把 SOP 交给 AI，而是把业务能力，拆成机器可执行、可验证、可迭代的规则。

人的经验隐性的做事方式
SOP结构化流程文档
Skill可调用的能力模块
业务资产可复用、可进化

对应三次本质变化：经验显性化 → 规则自动化 → 能力资产化

六步，每一步只回答一个核心问题

步骤核心问题做什么过关标准
① 筛选什么能力值得沉淀？把 SOP 切成一个个能独立交付的任务，按重复（常做、多人做）、代价（做错亏钱或返工）、隐性（靠某个人的经验）三项打分选定一个主任务。三项里占两项才值得做；整条 SOP 别当成一个 Skill，第一次只做最痛的那一段
② 拆解每一步是 Data / Code / Rule / LLM / Action 的哪一种？数据（事实从哪里来）、计算（哪些交给代码）、规则（什么情况怎么处理）、判断（哪些交给模型）、动作（最终改变什么）每步只有一种主类型；对外有副作用的动作都标出来，不可撤销的一律留人工闸
③ 显化指标、条件、阈值、动作分别是什么？把隐性经验写成显性规则：指标定义、条件明确、阈值写清、动作写死。例："ACOS 太高" → "ACOS > 2×利润率"每条规则，一个没参与过的人拿着数据能复核出同样的结论
④ 封装Goal / Context / Rules / Action / Eval 怎么写？Skill = 要解决什么问题 + 需要哪些信息 + 按什么规则执行 + 输出什么结果或动作 + 如何评估与校验找一个没参与的人，只读 Skill 包，能独立跑完一个案例
⑤ 验证是否比人工基线更稳定、更好？用真实案例检验：正常的、优秀的、失败的、边界的都要有；和人按原 SOP 做的结果并排比人工当时做错的那个案例，Skill 能拦住；同一案例多跑几次，结论基本一致
⑥ 迭代错误和反馈如何回流？版本记录、错误沉淀、反馈回流、更新规则。错误分三类回写：规则缺失 → 补规则；规则错误 → 改阈值；执行偏差 → 补检查项任何一条错误，都能追溯到一次具体的规则改动

开工之前还有个"第 0 步"：收料。把 SOP 的视频、文档、口述都收齐，整理成一份原文档案，每句话标清楚是事实（原文明说的）、推断（整理时补的）还是缺口（原文没说、但执行时必须知道的）。视频里演示的和文档写的不一致时，以视频为准——视频才是实际做法。

能算死的，交给代码确定性、规则化的问题，用代码最可靠
高风险动作，保留人工确认涉及资金、合规、对外决策的，必须有人把关
AI 放大 SOP，不替代判断让 AI 做更多、更快、更好的执行，关键判断仍需要人的经验与责任

核心难点：隐性经验显性化

SOP 里通常这么写

"检查竞品情况，判断竞争是否激烈。"

写给懂行的人看，足够了。老手一眼就知道该看什么。

Skill 里必须写到这个程度

  • 看哪个数（指标）
  • 什么情况下（条件）
  • 具体到数字或几个明确的档位（阈值）
  • 过、卡、还是拒；卡住了找谁（动作）

碰到"凭经验"的步骤，这样追问：你上次说"不行"，当时看到的是什么数字或现象？有没有例外，例外是怎么判断的？数据缺了一项，你是按 0 算、按最坏算，还是停下来？两个候选都及格，你怎么排先后？

实在写不成数字的，可以留给模型裁量，但必须配一张判级表（比如严重 / 一般 / 轻微各自是什么意思）和固定的几个输出选项，不许自由发挥。阈值写成"合理""明显"的，一律打回。

两个容易想错的地方，点开看

老员工说"这个我看一眼就知道行不行"，这种经验怎么转成规则？
别让他"总结"，让他边做边说。人总结自己的经验时，说出来的往往是教科书版本，真正起作用的那些判断他自己都没意识到。拿几个真实案例让他当场判，你在旁边追问上面那四个问题，尤其是"你刚才为什么直接跳过了这个"。被他跳过的地方，往往就是最值钱的那条隐性规则。
Skills 跑出来的结果从来不出错，是不是说明它已经很好了？
不一定，要看它是不是什么都不敢推荐。只测"不犯错"、不测"找得到"，很容易养出一个永远说"再看看"的 Skills——它确实不会错，但也没用。验证的时候两头都要看：该拦的拦住了没有，该找出来的找出来了没有。

FEYNMAN · 输出倒逼输入

老板说："我们那份 3 页的选品 SOP 写得很清楚了，直接喂给 AI 不就行了？"
请解释为什么不行，以及六步里哪一步最难、难在哪。

  • SOP 是写给懂行的人看的，省略掉的那些隐性判断，恰恰是 AI 最缺的
  • 最难的是"显化"：要把"我觉得不行"追问成指标、条件、阈值、动作，做到第三个人拿着数据能复核
  • 封装完不算完：用历史真实案例和人工结果并排比，对外有副作用的动作留人工确认，最后拍板的仍然是人
练拿真 SOP 练一把直播作业 4 · 篇章收官
任务
选择你的一个 SOP，按六步改造为 Skills。别挑整条流程，挑其中最痛的一段。
合格标准
"重复 / 代价 / 隐性"三项里至少占两项；六步每一步都有产出；显化出不少于 3 条原 SOP 里没写的判断；用至少 1 个历史真实案例回测，和当时的人工结论并排对比；对外有副作用的动作留了人工确认。
反馈闭环
每次人工验收打回，就按"规则缺失 / 规则错误 / 执行偏差"归一类，回写一条。每次用完留一句反馈：对、错、还是哪里别扭。
衡量口径：历史案例回测里，Skills 和人工结论一致的比例；单次用时从 __ 到 __。这些线都是起步值，按你的业务调。
  • 选定一段 SOP，三项打分过关
  • 六步每一步都有产出物
  • 用历史真实案例回测，和人工结论并排比
  • 建好错误回写表，第一条反馈已回写

本页 Takeaway：SOP 转 Skills 走六步，最难的是把隐性经验显化成"指标、条件、阈值、动作"；能算死的交给代码，高风险动作保留人工确认，AI 放大 SOP、不替代判断。直播的收尾也放在这里：不存在你什么都不懂还能用 AI 把事做成，但你可以用 AI 学会任何事情。
